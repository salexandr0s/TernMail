Expanded SwiftUI performance audit, 2026-11-02

This preventive audit started from `d05663c` in the independent TernMail checkout. No specific slowdown or Instruments trace was supplied. Review covered mail and search, reader rendering, attachments and images, Calendar, Tasks, assistant streaming and formatting, compose, analytics, organization, settings, account updates, and background maintenance. Findings establish unnecessary work or incorrect resource lifetime through source review and controlled probes; they do not establish an end-to-end CPU, scrolling, or memory improvement.

The audit follows the swiftui-performance-audit skill. Checks ran on Apple silicon with macOS 27.2 and Xcode 26.3. Independent review covered the fix plans and final source changes.

Fixes, ordered by expected impact:

1. Cancelled avatar loads retained decoded images outside the cache budget. [ContactThumbnailCache.swift](../App/Design/ContactThumbnailCache.swift) checked caller cancellation before removing completed pending work. Twenty cancelled requests reproduced twenty retained tasks while the resident-byte counter remained zero. Requests now track their waiters, reject already-cancelled callers, and remove shared work when its last waiter leaves. Work identity protects replacement requests from late cleanup. Tests cover cancellation during decoding, account removal, pressure purges, and multiple callers when the image exceeds the cache capacity. Confidence: high.

2. Task rows repeatedly filtered the full task list and searched it for parent titles. [GoogleTasksModel.swift](../App/Tasks/GoogleTasksModel.swift) now prepares open/completed arrays and parent titles when task values change. [GoogleTasksSidebar.swift](../App/Tasks/GoogleTasksSidebar.swift) captures its editor-adjusted rows and final row ID once per render. Ordering, stable task identity, and editors for remotely completed or removed tasks are preserved. Regression coverage checks in-place edits, completion, deletion, renamed parents, and unchanged snapshots. Confidence: high.

3. Assistant rendering repeated Markdown parsing and published scroll bookkeeping through view state. Each message in [AssistantConversation.swift](../App/Assistant/AssistantConversation.swift) now owns a lazy presentation for its immutable text revision. Chat and compose reuse those blocks; changing text replaces the helper without changing another message copy. Full-response copying still uses its separate unbounded formatter. [AssistantConversationView.swift](../App/Assistant/AssistantConversationView.swift) observes only changes to follow mode; scroll geometry stays unobserved. Tests cover reuse, append/reset, copy independence, display limits, and scroll-follow transitions. Confidence: high in the removed work; its previous UI frequency was not profiled. Parsed blocks remain retained with each viewed message revision, trading memory for reuse. Distinct streamed text updates still parse.

4. Calendar mini-months repeatedly rebuilt markers, and the sidebar repeatedly selected and sorted agenda entries. [CalendarPresentationSnapshot.swift](../App/Calendar/CalendarPresentationSnapshot.swift) now prepares markers and agenda ordering with the range. [CalendarMiniMonth.swift](../App/Calendar/CalendarMiniMonth.swift) and [CalendarSidebar.swift](../App/Calendar/CalendarSidebar.swift) reuse them only with matching calendar settings and date coverage. The sidebar uses its independent month snapshot. Tests preserve source color order, simultaneous-event order, daylight-saving boundaries, exclusive all-day ends, and year-boundary fallback. Preparation becomes more expensive once per range; warm lookups become cheaper. Confidence: high.

5. Account profile photos still decoded on the main actor. [AccountProfileImages.swift](../App/Design/AccountProfileImages.swift) now performs ImageIO decoding on a serial actor and creates the bounded NSImage on main. Publication and deferred cleanup recheck the account generation after suspension, so an obsolete decode cannot restore a signed-out photo or erase a newer refresh. Tests cover image bounds and delayed decoding during replacement/removal. Confidence: high in execution placement; visible latency is unmeasured.

6. Calendar file import, pasted ICS parsing, and post-panel export/write ran on the UI actor. [CalendarImportExport.swift](../App/Calendar/CalendarImportExport.swift) now runs that work in cancellable background tasks, retaining security-scoped URL access for the complete operation. [CalendarView.swift](../App/Calendar/CalendarView.swift) owns an identifiable import request; replacement or disappearance cancels it, and stale results cannot open the review. Tests cover file/text round trips, size limits, cancellation before reading, and preservation of an existing file when export is already cancelled. Confidence: high.

Timings are medians of seven trials after warmup, with matching checksums. Probes compile production-code extracts with Swift optimization, supporting stubs, and synthetic access loops; task and calendar probes link Debug-built GmailAPI dependencies. The Tasks timing excludes initial projection construction: preparation now runs on task mutation and retains arrays and a title lookup, whose preparation-time and retained-memory deltas were not measured. The image probe uses small domain stubs with actual cache code and AppKit/ImageIO. These isolate component work and do not include SwiftUI drawing, physical input latency, or total application memory. Probe sources, test logs, and result bundles are under `build/Verification/swiftui-expanded-audit/`.

Existing safeguards checked during review include stable account-qualified mail identities, native mail selection isolated from visual rows, cached mail projections, viewport-limited WebKit bodies, background HTML/resource preparation, bounded image caches, paginated attachment collections, lazy assistant transcripts, cancellable recipient queries, debounced draft persistence, detached calendar range preparation, and asynchronous analytics/Spotlight work. The earlier [mail-focused audit](swiftui-performance-audit.md) describes an older snapshot: its eager-reader and main-actor resource-processing hypotheses are superseded by the current implementation.

Remaining candidates need representative runtime evidence before further changes:

- Both assistant models publish their message collection for every streamed delta. Coalescing could help, but must preserve completion, error, cancellation, and final-token delivery.
- Compose serializes the attributed document on edits and builds plain text for placeholder visibility. Large drafts and image paste need a typing trace; changing empty-document semantics or attachment preparation without one would risk behavior for uncertain benefit.
- Writing-style persistence performs bounded synchronous file work on main. Changing its consent and startup lifecycle warrants a separate plan. Cache trimming and saved-attachment path checks also contain synchronous filesystem operations; slow-volume measurements would establish their impact.
- Small analytics/chart scans, account preference sorting, organization filtering, and repeated FlowLayout measurement remain possible costs. Their inspected uses do not justify additional caches or broad observation changes yet.

Further profiling should use a Release build on the same Mac, window geometry, and dataset. Capture SwiftUI and Time Profiler while scrolling/selecting mail, moving through calendar months/year view, scrolling a long assistant reply during streaming, and typing a large draft. Keep cold/warm captures separate and record avatar-cache memory after repeated scrolling. Compare body evaluations, main-thread samples, hitches, and allocations. Historical navigation targets in [performance.md](performance.md) were not remeasured by this audit.

Verification passed: 191 app tests in 17 suites, with no failures or skips, and an arm64 Release build. Final build/test validation used a frozen copy of `d05663c` with only the 22 audit source/test files overlaid. `source-manifest.json` records their hashes and snapshot location. Two native visual audit suites also passed, producing 16 captures; four representative assistant/calendar captures were inspected in light and dark appearances at narrow widths. Report links and scoped whitespace checks passed. No separate Core source, project, or dependency changes belong to this audit.
